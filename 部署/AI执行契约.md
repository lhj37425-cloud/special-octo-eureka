# AI 执行契约（部署协助）

> 本文给协助部署的 AI 助手看。步骤编号与《上线部署手册（前辈版）》一致（S00–S12），前辈版写"在做什么"，本文写"你必须遵守什么"。

## 角色与目标

- 目标：按 S00–S12 协助完成部署，每步给出命令、读输出、判断是否通过。
- 非目标：优化配置、修代码、改数据、做文档外的"顺手改进"。

## 权威文件与冲突处理

1. `部署/部署事实.json` 是端口、路径、数据量、禁止事项的唯一事实源。
2. 任何文档、记忆、惯例与事实文件冲突时：**停止，向操作者报告冲突点，等待指示**。不要自行选择"看起来更对"的那个。

## 硬约束（违反即事故）

- 不改 `data/` 下任何文件；不手改 `state.json`；内容问题一律让操作者走后台页面。
- 不把 4173/4181 绑到 `0.0.0.0`；不在公网可达的状态下留 `initialized:false` 的后台。
- 不跳过门禁：S05 不过不配 Nginx；S10 不全 PASS 不建议切 DNS/宣布上线。
- 不执行 `rm`、`dd`、`mkfs`、磁盘分区、防火墙整体关闭类命令；不删 `/srv/backup` 任何文件。
- 不把密码、会话 Cookie、完整留言内容写进日志、报告或对话。
- 证书顺序固定：HTTP-only 临时配置（S06）→ certbot（S07）→ 正式配置（S08），不得调换。

## 执行模型

对每一步 Sxx：

1. **前置**：确认上一步的判定标准已通过；没通过不进入本步。
2. **命令**：只执行手册里的命令或等价的只读检查命令；需要偏离时先说明理由并征得操作者同意。
3. **判定**：对照手册"预期输出/期望状态码"，逐字核对，不凭印象说"看起来好了"。
4. **失败动作**：执行手册该步的"失败处理"；处理不了 → 保存证据（见下）→ 停止并报告。
5. **记录**：每步命令和完整输出追加保存到 `~/evol-deploy/部署日志/<日期时间>/Sxx.log`。

## 停止条件（命中任何一条立即停）

- 实际输出与手册预期不符，且手册"失败处理"没有覆盖。
- `sha256sum -c` 出现 FAILED；数据快照数字与事实文件不符。
- 需要权限/密码/域名面板操作等你没有的信息。
- 发现服务器上已有未备份的站点或数据。
- 操作者要求"先跳过验证试试"——解释门禁理由，仍坚持则停下来由人负责。

## 已知问题（上线窗口不修，只记录）

- 课程/专家详情页的 `og:title`/`og:description` 用首页文案（SEO 小项，不影响功能）。
- 预览视频 Range 已支持；如遇到极个别浏览器拖不动进度，记录版本号即可。
- Render/Replit 免费测试站与正式部署无关，不要把测试站配置带进生产。

## 交接报告模板（结束后输出）

```
部署日期 / 服务器（OS、IP 段即可）/ 执行人
包版本：tag + commit + SHA256 首 8 位
逐步结果：S00…S12 各 PASS/FAIL（FAIL 附日志文件名）
S10 验证：脚本退出码、抽查 URL 数、手工项勾选情况
遗留事项：无 / 列出（每条带负责人）
回滚就绪：最近备份文件名 + 位置
```
