# 前辈拿到包后的验收清单

> 目标：在动手部署前，用 15–30 分钟确认“包是完整的、环境是对的、文档是自洽的、出问题能回滚”。
> 任何一项打不上勾，先停下来联系交付人，不要靠经验猜。
> 数字、路径、端口以 `部署/部署事实.json` 为准；步骤以 `部署/上线部署说明.md` 为准。

## 0. 先不要做

- 不要先看业务代码；
- 不要先解压 `data/` 到正式目录；
- 不要在没校验 SHA256 前解包；
- 不要在服务器已有旧站、且没备份 `/etc/nginx` 和旧数据时直接覆盖；
- 不要让 AI 直接执行部署、certbot、DNS、恢复数据；先让它做只读审计。

## 1. 包完整性（约 5 分钟）

```bash
mkdir -p ~/evol-deploy && cd ~/evol-deploy
# 交付的三个文件必须在这里：
#   evol-app-v1.0-deploy.tar.gz
#   evol-data-v1.0-deploy.tar.gz
#   SHA256SUMS
sha256sum -c SHA256SUMS
# 预期：两个包都是 OK
```

- [ ] app 包、data 包、SHA256SUMS 三个文件齐全
- [ ] `sha256sum -c` 两个都 OK
- [ ] `tar tzf evol-app-*.tar.gz | head` 能看到 `server.js`、`部署/` 等
- [ ] `tar tzf evol-data-*.tar.gz | awk -F/ 'NF<=3'` 能看到 `admin-backend/`、`mvp-leads.json`，没有多套一层 `data/`
- [ ] 包内 `部署/部署事实.json` 的 `release.tag` 与交付包名一致（当前 `v1.0-deploy`）

任何一项失败：停止，不要尝试修复数据文件，联系交付人重新拿包。

## 4. 如果服务器已有旧站（先做备份）

```bash
sudo cp -a /etc/nginx "/etc/nginx.backup-$(date +%F-%H%M)"
sudo nginx -T > ~/evol-deploy/nginx-before.txt 2>&1
sudo ss -tlnp | grep -E ':80|:443'
sudo crontab -l > ~/evol-deploy/crontab-before.txt 2>/dev/null || true
# 旧站数据/数据库/上传目录按实际情况备份
```

- [ ] 已备份 `/etc/nginx`
- [ ] 已记录旧站端口和 server_name
- [ ] 已备份旧站数据/数据库/证书/crontab
- [ ] 已决定：先测试域名/端口验证，还是原地切换
- [ ] 已准备旧站回滚命令
