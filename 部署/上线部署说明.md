# 上线部署说明（Linux + Nginx）

配套文件：
- `nginx.conf` — 反代配置（前台 4173、后台 4181、后台挂 `/admin/`）
- `evol-front.service`、`evol-admin.service` — systemd 守护，崩溃自动重启
- `../上线验收报告.md` — 验收结论与问题清单

## 一、目录与端口约定

| 项 | 值 |
|---|---|
| 代码根目录 | `/srv/evol` |
| 数据目录 | `/srv/evol/data`（含 `admin-backend/`） |
| 前台 | `127.0.0.1:4173` |
| 后台 | `127.0.0.1:4181`，对外是 `https://www.evoldream.tech/admin/` |
| 运行用户 | `www-data` |

两个服务都只监听回环地址，由 Nginx 对外，**不要**改成 `0.0.0.0` 直接暴露。

## 二、环境变量（已写进 service 文件）

| 变量 | 前台 | 后台 | 作用 |
|---|---|---|---|
| `PORT` / `ADMIN_PORT` | 4173 | 4181 | 监听端口 |
| `MVP_DATA_DIR` | `/srv/evol/data` | 同左 | 咨询留言 `mvp-leads.json` |
| `ADMIN_DATA_DIR` | `/srv/evol/data/admin-backend` | 同左 | 内容、账号、上传、备份 |
| `ADMIN_BASE_PATH` | `/admin/` | — | 预览页"返回编辑"链接指向同域后台 |
| `HOST` | `127.0.0.1` | `127.0.0.1` | 监听地址，容器内可改 `0.0.0.0` |

> 两个服务都要拿到 `MVP_DATA_DIR` 和 `ADMIN_DATA_DIR`：前台读发布快照和留言，后台读内容并写留言状态。

## 三、首次部署步骤

> **动手前逐项确认（部署前检查单）**
>
> 1. 本地 `data/admin-backend/state.json` 里的 `"sessions"` 已清空为 `{}`——不把本地登录会话带上服务器。
> 2. `data/mvp-leads.json` 含客户姓名和电话，上传后权限收紧为 640（命令见第 3 步）。
> 3. 主管理员密码 ≥ 10 位、含大小写字母和数字，不要用弱口令。
> 4. 传完数据、开 Nginx 之前，必须先确认后台已识别到账号（第 5 步的 `/api/status` 检查）：返回 `{"initialized":true}` 才能继续。为 `false` 说明数据没传完整，此时**任何人都能 POST /api/setup 抢注主管理员**，绝不要在这时候把端口暴露到公网。

```bash
# 1. 服务器准备（Debian/Ubuntu）
sudo apt update && sudo apt install -y nginx
node -v   # 需要 >= 18，没有就装 NodeSource 的 LTS

# 2. 放代码（本地上传，排除 node_modules 和 data）
sudo mkdir -p /srv/evol
sudo rsync -av --exclude node_modules --exclude data ./ user@server:/srv/evol/

# 3. 放数据（本地已有全量备份，再传一份）
sudo rsync -av data/ user@server:/srv/evol/data/
sudo chown -R www-data:www-data /srv/evol/data
sudo chmod 700 /srv/evol/data/admin-backend
sudo chmod 640 /srv/evol/data/mvp-leads.json   # 含客户姓名电话，收紧权限

# 4. systemd
sudo cp 部署/evol-front.service 部署/evol-admin.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now evol-front evol-admin
sudo systemctl status evol-front evol-admin --no-pager

# 5. 本机自检（此时还没配 Nginx，端口只监听回环，是安全的）
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4173/vi/    # 期望 200
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4181/       # 期望 200
curl -sS http://127.0.0.1:4173/healthz                                 # 期望 {"ok":true}
curl -sS http://127.0.0.1:4181/healthz                                 # 期望 {"ok":true}
curl -sS http://127.0.0.1:4181/api/status
# ↑ 必须返回 {"initialized":true}，为 false 就停下检查数据是否传完整，不要继续

# 6. Nginx + 证书
# 顺序不能反：全新服务器上证书文件还不存在，直接放带 ssl_certificate 的配置，
# nginx -t 必失败，certbot 也无法接管。先 HTTP-only 拿证书，再覆盖正式配置。

# 6.1 先放一份临时 HTTP-only 配置（假设当前目录是 /srv/evol）
sudo tee /etc/nginx/conf.d/evol.conf >/dev/null <<'EOF'
server {
    listen 80;
    listen [::]:80;
    server_name evoldream.tech www.evoldream.tech;
    location / { return 200 'ok'; add_header Content-Type text/plain; }
}
EOF
sudo nginx -t && sudo systemctl reload nginx
# 预期输出：nginx: the configuration file ... syntax is ok / test is successful

# 6.2 签证书（先确认两个域名 DNS 已解析到本机）
sudo certbot --nginx -d www.evoldream.tech -d evoldream.tech
# 预期末尾输出：Successfully deployed certificate ... Congratulations!
# certbot 会顺带把这份临时配置改成 443，不用管，下一步会整体覆盖

# 6.3 用正式配置覆盖，再 reload
sudo cp 部署/nginx.conf /etc/nginx/conf.d/evol.conf
sudo nginx -t && sudo systemctl reload nginx
# 预期输出：syntax is ok / test is successful

# 6.4 如果域名走 Cloudflare 代理（橙云），额外两件事：
# ① CF 面板 SSL/TLS 加密模式必须选 Full (Strict)，不能是 Flexible，
#    否则 CF 到 Nginx 走 http，后台登录 Cookie 不会带 Secure
# ② 在 /etc/nginx/conf.d/evol.conf 的 443 server 块里（ssl_certificate 行之后）
#    还原真实访客 IP，否则限流和留言风控把所有访客当成同一个 CF 节点 IP：
#      real_ip_header CF-Connecting-IP;
#      set_real_ip_from 173.245.48.0/20;
#      set_real_ip_from 103.21.244.0/22;
#      ...（CF 全部网段见 https://www.cloudflare.com/ips ，v4 和 v6 都要列）
#    改完 sudo nginx -t && sudo systemctl reload nginx
```

## 四、上线后自检（必做）

```bash
# 首页与三语
curl -sSI https://www.evoldream.tech/ | head -1                 # 302 → /vi/
curl -sS -o /dev/null -w '%{http_code}\n' https://www.evoldream.tech/zh/
curl -sS -o /dev/null -w '%{http_code}\n' https://www.evoldream.tech/en/training/

# 安全响应头
curl -sSI https://www.evoldream.tech/zh/ | grep -iE 'strict-transport|x-frame|referrer'

# 健康检查 / robots / sitemap
curl -sS https://www.evoldream.tech/robots.txt | head -3       # 期望 User-agent: * 开头
curl -sS https://www.evoldream.tech/sitemap.xml | head -2      # 期望 <?xml ... <urlset ...
curl -sSI https://www.evoldream.tech/admin/ | grep -i x-robots-tag    # 期望 noindex, nofollow
# 静态资源仍带安全头（验证 add_header 块里安全头重写生效）
curl -sSI https://www.evoldream.tech/favicon.svg | grep -iE 'strict-transport|x-frame|cache-control'

# 后台登录页
curl -sS -o /dev/null -w '%{http_code}\n' https://www.evoldream.tech/admin/
curl -sSI https://www.evoldream.tech/demo.js | head -1          # 200
```

浏览器手动确认（用真实域名，不要用 IP）：

1. 三语首页、课程页、专家页、案例页各看一遍，图片和视频能加载。
2. 打开 `/admin/` 登录 → 登录后 Cookie 里 `admin_session` 应带 `Secure`、`HttpOnly`。
3. 后台编辑内容点"预览" → 应打开 `https://www.evoldream.tech/preview/...`（不是 `http://`、不带端口）。
4. 预览页顶部"返回编辑" → 回到 `/admin/`。
5. 前台提交一条真实留言 → 后台"咨询留言"能看到；24 小时内确认多个人提交不会被互相互锁（这是 P0-1 修的东西）。
6. 后台传一张图 → 保存草稿 → 预览 → 发布 → 前台刷新可见。
7. 手机真机看首页和课程页。

## 五、备份

```bash
# 一次性：建备份目录并授权给 www-data（cron 以 www-data 运行，目录不存在会直接失败）
sudo mkdir -p /srv/backup && sudo chown www-data:www-data /srv/backup

# 每天 3:30 打包数据目录（state.json + uploads + 留言），保留 14 天
sudo tee /etc/cron.d/evol-backup >/dev/null <<'EOF'
30 3 * * * www-data tar czf /srv/backup/evol-$(date +\%F).tar.gz --exclude='data/admin-backend/backups' -C /srv/evol data && find /srv/backup -name 'evol-*.tar.gz' -mtime +14 -delete
EOF
```

说明：
- `--exclude='data/admin-backend/backups'`：后台自带备份目录（单份约 65MB）**不打进每日包**，否则每天约 377MB、14 天近 5GB，磁盘迟早撑满。后台自带备份已改为只保留最近 10 份，不会再无限增长。
- 异地备份建议**加密后再传**（包里有客户留言和账号哈希）：例如打包后 `gpg -c`，或用 rclone 的 crypt 模式同步到对象存储。

## 六、更新上线

```bash
cd /srv/evol
sudo -u www-data git pull            # 或 rsync 新代码，不要覆盖 data/
sudo systemctl restart evol-front evol-admin
curl -sS -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4173/vi/
```
**不要**在更新时动 `data/`。任何内容改动都走后台页面，不要手改 `state.json`。

## 七、回滚

```bash
sudo systemctl stop evol-front evol-admin
sudo tar xzf /srv/backup/evol-<日期>.tar.gz -C /srv/evol
sudo chown -R www-data:www-data /srv/evol/data
sudo systemctl start evol-front evol-admin
```

## 八、排查

| 现象 | 原因 |
|---|---|
| `nginx -t` 报 `ssl_certificate ... No such file or directory` | 证书顺序错了：先放 HTTP-only 临时配置跑 certbot 拿证书，再覆盖正式配置（见三.6） |
| CSS/JS/SVG 响应缺 HSTS 等安全头 | 该 location 里写了 `add_header` 导致 server 级安全头不再继承，按 `部署/nginx.conf` 的写法在块内把 4 个安全头重写一遍 |
| 表单提交返回 403「请求来源校验未通过」 | Nginx 没传 `Host` 或 `X-Forwarded-Host`，检查 `proxy_set_header` |
| 登录后 Cookie 没有 `Secure` | Nginx 没传 `X-Forwarded-Proto $scheme` |
| 预览返回 401「请先登录后台再预览」 | 后台和前台不在同一域名下（用了 `admin.` 子域），改回同域 `/admin/` 方案 |
| 上传大视频报 413 | `client_max_body_size` 小于 60m，或没设 `proxy_request_buffering off` |
| 后台样式丢失、按钮点不动 | `/demo.css`、`/demo.js` 等 6 个绝对路径没指到 4181 |
| 留言第 6 个人被拒 | 反代没传 `X-Real-IP` / `X-Forwarded-For`，所有人都被当成同一个 IP |
